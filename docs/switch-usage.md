# How WOYM uses Switch

One Switch room, bridged to Mattermost `#acme-support`, holds agents owned by **two different Switch users**: three vendor agents owned by `dev`, and `acme-env`, owned by the customer `meera`. Switch, not our code, decides who may address whom. Our code adds checks on top (sender ids, consent words, loop guard) but never replaces Switch's rule.

Evidence tags:
- **[live-verified]**: seen on the local Switch 0.31.0 stack, in the kill test (`docs/switch-notes.md` §0) or the live M1/M2 demo runs (`PLAN.md` §5: M1 live in 15.7 s, M2 live in 28.6 s with the fixture fixer).
- **[fake-tested]**: exercised by our tests against a fake Switch (`tests/agents/fakeswitch.py`, which drives the real `WsSwitchClient`), but not separately observed live.

## Features we use

| Switch feature | What it is | Where (file:function) | What it does in the demo | What breaks without it | Evidence |
|---|---|---|---|---|---|
| **Per-owner registration keys and agent owners** | Each Gateway user mints their own registration key; an agent registered with it is owned by that user | `woym/switch/setup.py:main` (`POST /gateway/users`, `POST /gateway/api-keys`), `setup.py:register_agent` (`POST /agents`) | `triage`, `runner` and `fixer` belong to dev; `acme-env` belongs to meera. Each one's owner is shown in its display name | There'd be no second party, just one vendor talking to itself, and the cross-owner rule below would have nothing to enforce | [live-verified] kill test #1–2 |
| **Addressing policy (Meera's rule)** | Per-agent allow rules: deny by default, settable only by the owner | `woym/switch/setup.py:main`: meera's `PUT /gateway/agents/{acme}/addressing-policy` = meera + meera's agents + `triage`; dev sets `triage` to open | Only `triage` (and Meera) can direct `acme-env`. `runner` and `fixer` can't, even though they're in the room | The customer agent would take instructions from any vendor agent or human. The trust story ("Switch-enforced, not just our code") falls apart | [live-verified] kill test #3: `not_permitted` before the rule, `live` after; dev changing Meera's rule → 403; an agent changing its own rule → 403 (#3b) |
| **The refusal** | When a message addresses an agent whose rule doesn't admit the sender, Switch posts a visible auto-reply from that agent | Server-side. Our agents ignore it: `woym/case/state.py:should_ignore` plus untagged-message handling in `woym/agents/triage.py:on_chat` / `acme_env.py:on_chat`. Tested in `tests/agents/test_flow.py::test_greetings_refusals_and_notices_are_ignored` and the integration test | Can be shown on camera: a vendor human @-mentioning `acme-env` gets "I only take instructions from my owner…" | Without it, a refused message would fail silently. With it, our agents must not mistake the auto-reply for real work, which they don't | Refusal [live-verified] kill test #3; our agents ignoring it [fake-tested] |
| **`send_targeted` vs `post`** | `send_targeted_message` addresses named agents and returns a per-target status. `post_message` just posts (but an `@name` inside it ALSO addresses) | `woym/agents/base.py:Agent.send` (every agent-to-agent hop) vs `Agent.say` / `Agent.announce` (cards to the room) | Every hop of the 20-step flow is a `send_targeted` with a fixed recipient in code. Cards are `post`s. A non-`live` status is shown in the thread ("⚠️ acme-env is `not_permitted`…", `triage.py:_hop_out`) | Without statuses we couldn't tell a refused hop from a slow one. If our prose @-mentioned agents, it would trigger refusals on camera, so no agent ever writes `@<agent>` (enforced by the fakes and `tests/case/test_card.py::test_no_card_mentions_an_agent`) | Statuses [live-verified] kill test #3; `@name` addresses [live-verified] §0 "Surprises"; our no-mention rule [fake-tested] |
| **Threads / `thread_id`** | Messages can reply into a thread; `thread_id` is the Switch id of the root | `woym/agents/triage.py:_open_case` (case thread = the report's message id), `woym/case/state.py:CaseStore.by_thread`; every send passes the case `thread_id` | One Mattermost thread per case, rooted at Meera's report. Consent counts only in that thread (`woym/case/consent.py:evaluate`) | Cases would interleave in the channel, and a "yes" from another conversation could count as consent | [live-verified] kill test #5, #9; thread-scoped consent [fake-tested] |
| **`list_participants`** | Room roster: id, name, type (agent/user), status | `woym/switch/client.py:WsSwitchClient._refresh_kinds` | Tells the client which senders are agents and which are humans, so `triage` only takes commands from humans and only takes replies from the agent that owns each step (`triage.py:STEP_SENDER`) | A human could post a message carrying a tag and be treated as an agent reply | [live-verified] (ids are UUIDs; kinds mapped by name, switch-notes §0c) |
| **`read_context`** | Room history, as threads | `woym/switch/setup.py:main` / `wait_for_greetings`: reads each human's exact `sender` id and waits for the join greetings. `WsSwitchClient.thread` wraps it | Setup records `humans.<h>.switch_participant_id`; `triage.py:_is_human` then checks senders by **id**, not just by name | Sender checks would fall back to display names, which are easier to spoof | Reading ids [live-verified] §0c; the agents' own `thread()` path isn't used by any agent at runtime |
| **WebSocket connection + pings** | One WS per agent: `connection_state`, `message` frames, a ping every 2 s answered with a pong (6 s TTL) | `woym/switch/client.py:WsSwitchClient._session` (pongs), `run` (reconnect with backoff), `_on_message` (skips own messages) | All four agents stay connected for the whole case, even during a 90 s sandbox run (handlers run on a worker task, so pongs are never blocked) | Agents would lapse mid-bisect, and replies would be lost or queued | [live-verified] kill test #2 (14 s, no eviction) and the live M1/M2 runs |
| **Mattermost bridge** | Switch room ↔ Mattermost channel; humans post as their real MM accounts | `woym/switch/setup.py:main` (`POST /gateway/rooms` with the MM `bridge_id`), `scripts/humans.py` (scripted human lines, labelled as such) | Meera reports the bug and says "yes" from Mattermost; every card renders there as markdown | There'd be no human-visible room: the consent and the cards would have no audience | [live-verified] kill test #5, #7, #9 |
| **Identity links** | A Mattermost account linked to a Switch user, so `owner:true` rules match that human | `woym/switch/setup.py:main` (`POST /gateway/collaborations/{bridge}/identities` for dev and meera) | Meera, as herself in Mattermost, counts as `acme-env`'s owner | Meera's messages wouldn't match her own agent's `owner` rule | [live-verified] kill test #8 (`addressed:true` after linking, not before) |
| **Display names** | The owner sets an agent's display name, and Switch renames the MM bot | `woym/switch/setup.py:brand_agents` (`PUT /gateway/agents/{id}/name`, `LABELS`) | Every agent post shows its owner, e.g. "acme-env · owner: meera (Acme)" | Viewers couldn't see which side each agent works for, which is the whole point of a two-owner room | [live-verified] switch-notes §0b |
| **The room as consent and audit log** | The thread itself is the record: request, consent question, exact values, yes, runs, result | `woym/case/card.py:consent_prompt`, `woym/agents/acme_env.py:on_tag` / `_env_answer` / `_verify`; the wire tag on every hop (`woym/case/tags.py`) | Meera sees exactly the 5 values before they're sent, and a second question before the fix is installed. Every hop carries a machine-readable `woym case=… step=…` line | Without it, data sharing and installs would be invisible and not auditable. "Works on your machine" would be a claim, not a record | Consent flow in the live M1/M2 runs [live-verified]; second install consent and refusal paths [fake-tested] |

## What we deliberately don't use, and why

| Feature | Why not |
|---|---|
| **Room documents** | Humans can't read them in Mattermost, and the audience for consent and results is the humans in the channel. Everything that matters is posted in the case thread |
| **Message edit** | There's no edit op for agents (kill test #6; only `edit_role` exists). Cards are re-posted, so the lineup card (⏳) is followed by the bisect card (✅/❌) |
| **Follow-ups** (`!follow-ups`) | Off on this server ("Following the conversation isn't switched on", kill test #5b). We rely on explicit addressing and thread scoping instead |
| **Bootstrap `AGENT_REGISTRATION_TOKEN`** | Agents registered with it belong to a separate non-admin account, which would hide the two-owner story. We mint per-owner keys instead |
| **LLM-chosen routing** | Switch delivers to whoever is addressed, so we never let a model choose recipients or steps. Every (step, recipient) pair is fixed in code (`woym/agents/*.py`), and the only LLM (`claude -p` in `@fixer`) writes code and one line of prose |
